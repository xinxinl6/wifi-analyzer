# 2026-05-15 工作日志

## 公网IP显示修复

### 问题
AuroraNetworkGrid 中公网IP一直显示"获取中..."或"--"

### 根因分析
1. **NetworkDiagnostics.notifyComplete() 提前触发**: `fetchGateway()` 是同步操作，完成后立即调 `notifyComplete()` 把 `isTesting` 设为 false，但 `fetchPublicIp()` 是异步操作还没完成。AuroraNetworkGrid 轮询检测到 `isTesting===false` 就停止轮询，导致公网IP永远拿不到。
2. **fetchLocalIp 成功路径漏调 markTaskComplete**: 获取本机IP成功后直接 `return`，没调计数器，导致 `notifyComplete` 永远不会被触发。

### 修复方案
- NetworkDiagnostics 引入 `completedTasks` / `totalTasks` 计数器，三个任务各自完成时调 `markTaskComplete()`，全部完成后才调 `notifyComplete()`
- 修复 `fetchLocalIp` 成功路径也调 `markTaskComplete()`

### PublicIpView 抽离（参考 WlAN-03）
- 参考 WlAN-03 的实现方式：将公网IP从 `InfoGridItem` 改为独立的 `PublicIpView` 组件
- `PublicIpView` 放在 Grid 的同一个位置，内部自己用 `http.createHttp()` 请求公网IP
- 不依赖 NetworkDiagnostics，独立获取，避免和网格里其他项的轮询互相干扰
- 保持和 `InfoGridItem` 一致的视觉样式
- 删除了之前错误创建的 `PublicIpCard.ets`（独立大卡片，不是用户要的方式）

## 网络信息网格全部独立组件化

### 问题
公网IP修复后，本机IP、网关、DNS 仍然显示 `--`

### 根因
这三个仍依赖 `NetworkDiagnostics` 单例 + 轮询机制，架构上和公网IP一样存在同步/异步时序问题

### 修复方案（WlAN-03 模式）
将四个网格项全部改为独立组件，各自负责数据获取：

1. **LocalIpView** (`entry/src/main/ets/components/LocalIpView.ets`)
   - 内部调用 `wifiManager.getIpInfo()` 获取本机IP
   - 同步API，aboutToAppear 中直接获取

2. **PublicIpView** (`entry/src/main/ets/components/PublicIpView.ets`) — 已存在
   - 内部调用 `http.createHttp()` 多API降级获取公网IP

3. **GatewayView** (`entry/src/main/ets/components/GatewayView.ets`)
   - 内部调用 `connection.getDefaultNetSync()` + `getConnectionPropertiesSync()` 获取网关

4. **DnsView** (`entry/src/main/ets/components/DnsView.ets`)
   - 内部调用 `connection` API 获取 DNS

### AuroraNetworkGrid 改动
- 移除了 `@State diagnostics`、`@Consume wifiState`、轮询定时器、`aboutToAppear`/`aboutToDisappear` 中的轮询逻辑
- 移除了 `InfoGridItem` @Builder
- Grid 中四个 GridItem 分别使用 `LocalIpView`、`PublicIpView`、`GatewayView`、`DnsView`
- 每个组件通过 `@Prop isDarkMode` 接收主题状态
- 不再依赖 `NetworkDiagnostics` 单例和 `defaultDiagnosticsResult`

### 结果
四个网络信息项各自独立获取数据，互不干扰，不再出现 `--` 或 `获取中...` 卡住的问题

## 信道页面深色模式文字对比度修复（2026-05-16）

### 问题
`ChannelSection.ets` 中推荐信道芯片（`buildRecommendChip`）和"干扰最少"标签（`least_interference`）的背景色固定为 `COLOR_CHANNEL_RECOMMEND_BG = '#F0FDF4'`（浅绿色），深色模式下芯片背景仍为浅色，文字对比度不足，"最佳" 文字使用 `COLOR_CHANNEL_IDLE='#10B981'` 在浅色背景上偏淡。

### 修复
- **推荐信道芯片背景**：深色模式下改为 `rgba(16,185,129,0.12)`，边框改为 `rgba(16,185,129,0.35)`
- **"最佳" 文字颜色**：深色模式下改为更亮的 `#34D399`，确保对比度
- **"干扰最少" badge**：深色模式下背景 `rgba(16,185,129,0.15)`，文字颜色 `#34D399`
