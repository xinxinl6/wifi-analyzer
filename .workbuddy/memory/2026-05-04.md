## 修复 ArkTS catch 子句类型注解错误

### 问题
ArkTS 编译器报错：`Type annotation in catch clause is not supported (arkts-no-types-in-catch)`

错误出现在 `NetworkDiagnostics.ets` 文件中的 6 处 catch 子句：
- 第 157 行: `} catch (wifiError: unknown) {`
- 第 193 行: `} catch (connError: unknown) {`
- 第 207 行: `} catch (error: unknown) {`
- 第 284 行: `} catch (error: unknown) {`
- 第 318 行: `} catch (parseError: unknown) {`
- 第 336 行: `} catch (error: unknown) {`

### 修复方式
移除所有 catch 子句中的类型注解：

```typescript
// 修改前（错误）
} catch (error: unknown) {

// 修改后（正确）
} catch (error) {
```

### 修复文件
`core/src/main/ets/network/NetworkDiagnostics.ets`

### 验证
修复后搜索项目中所有 `.ets` 文件，确认没有其他 `catch (.*: unknown)` 或 `catch (.*: any)` 的模式。

### 经验教训
- **ArkTS 限制**：ArkTS 不支持在 catch 子句中使用类型注解，必须使用裸 `catch (error)` 或 `catch (e)` 形式
- **与标准 TypeScript 不同**：在标准 TypeScript 中可以使用 `catch (error: unknown)`，但 ArkTS 禁止此写法

## AI 分析功能降级方案

### 问题
点击"AI 分析"后弹出"暂无可用打开方式"提示，说明小艺助手在当前设备/模拟器上不可用。

### 解决方案
为 `launchXiaoyi()` 函数添加降级方案：
1. **方案1**: 尝试直接启动小艺主界面
2. **方案2**: 尝试通过系统 Want 启动小艺
3. **方案3（降级）**: 如果前两个都失败，自动打开浏览器使用必应搜索

### 修改文件

#### 1. XiaoYiHelper.ets
- 函数 `tryLaunchBySearch` 改名为 `tryLaunchByBrowser`
- 使用必应搜索（`bing.com/search`）替代百度搜索
- 降级方案使用更友好的提示信息

#### 2. AuroraDashboard.ets
- catch 子句修复：`catch((err) => {...})` → `catch((error: Error) => {...})`
- 避免使用 `JSON.stringify(err)`，改用 `error?.message`

### 经验教训
- **小艺助手兼容性**：小艺助手 (`com.huawei.hiai`) 只在华为设备上可用，模拟器不支持
- **降级策略**：关键功能应提供降级方案，确保用户体验不被中断
- **catch 子句类型**：在 `.then().catch()` 链式调用中，catch 参数需要显式声明类型
