### P0-2: 多线程并行下载
- `SpeedTestEngine.ets`: 重写 `measureDownloadSpeed`，4 线程并行 Range 请求（各 5MB，共 20MB）
- `Promise.all()` 并发，总字节数 / 总耗时 = 精确 Mbps
- 移除旧的单线程逐级增量模式

### P0-3: HTTP HEAD Ping（接近 ICMP 精度）
- `SpeedTestEngine.ets`: `measurePing` 从 HTTP GET 改为 HEAD（无响应体，延迟更接近真实 RTT）
- 采样数从 4 → 6，去极值取中间 4 个算平均（抗干扰）
- ICMP 原生 Ping（NativePing）保留在 entry/utils/，HAR 模块隔离暂不能直接接入

## Bufferbloat 测量
- **SpeedTestResult**: 新增 `bufferbloatDownloadMs` / `bufferbloatUploadMs` 字段
- **Engine**: `measureDownloadWithBloat` + `measureUploadWithBloat` 方法，下载/上传时并行 `measureLoadedPing`（HTTP HEAD 持续测延迟）
- **计算**: 满载延迟 - 空闲基线延迟 = bufferbloat ms
- **评分**: <10ms 绿(优秀) / 10-50ms 黄(一般) / >50ms 红(差)
- **UI**: SpeedDetailCard 新增缓冲膨胀行，SpeedDetailPopup 详情也显示
- **智能选路**: 新增 `autoSelectBestServer()` — 并行 HTTP HEAD 所有节点，选 RTT 最低
- **真实下载**: 重写 `measureDownloadSpeed()` — 3轮逐级增量（2MB→8MB→20MB），基于实际字节/耗时精确计算 Mbps
- **删除假速度**: 移除旧的 `elapsed * 15 + random * 10` 模拟定时器
- **新方法**: `singlePing(url)` HTTP HEAD 快速测延迟，`getRangeSize(range)` 解析 Range 字节数
